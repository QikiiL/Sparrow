## 3. v0.9.3 富文本预览与可编辑（核心新架构）

一句话：**预览与编辑共用同一份 srcDoc（排版归一 + 主题配色），弹窗 iframe 开 designMode 做所见即所得，保存时把正文归一成「纯文本 + 语义 HTML」交给后端重新写 CF_HTML。**

### 3.1 `src/lib/richPreview.ts` —— 预览归一（只读 + 编辑共用）

- 导出：`readRichPreviewPalette()`（L91）、`buildRichPreviewSrcDoc(html, palette = readRichPreviewPalette())`（L113）。
- 调色板：从宿主 `documentElement` 计算样式读 `--surface / --text / --muted / --hair / --surface-2 / --accent / --sel`；读不到（jsdom、首帧）逐项回落浅色 `FALLBACK_PALETTE`。只接受「像颜色」的值（挡掉空串与含 `;{}<>` 的值）。
- iframe 内 CSS 分 10 段：
  1. `body *` 全量 reset（`background:transparent / color:inherit / font-* / line-height / margin / padding / border / max-height:none / overflow:visible / position:static / float:none / display:revert / width/height:auto / transform:none / opacity:1` 等，全 `!important`）；
  2. 语义排版：h1–h6 = 18 / 16 / 14.5 / 13.5 / 13 px（600 字重），正文 13px / 1.625，`p,div` 下边距 9px，列表 `padding-left:20px`，blockquote / hr / strong / em / a / mark；
  3. 行内 `code` 小胶囊（`--rp-surface-2` 底 + `--rp-hair` 边框 + 5px 圆角）；
  4. 代码块：`pre` 与 `[style*="pre-wrap"]` 统一成块级卡片（等宽字体、8px 圆角、内层滚动失效）；
  5. `[style*="position: sticky"]`（工具输出里的「输入/输出」小标签）降级成 11.5px 灰色小标题；
  6. `span:empty { display:none }`；
  7. 表格细边框、`caption`；
  8. 图片 `max-width:100% / height:auto / max-height:100%`（压掉 Outlook 的写死尺寸）；
  9. 细滚动条；
  10. 编辑态：`html{height:100%}`、`body{min-height:100%;box-sizing:border-box;caret-color:var(--rp-accent)}`、`body:focus{outline:none}`。
- CSP 仍为 `default-src 'none'; img-src data:; style-src 'unsafe-inline'`；**片段 verbatim 内嵌**（`<body>${html}</body>`），不做任何 DOM 重写。
- `ClipboardItem.tsx` 的悬停气泡复用同一 srcDoc（`src/components/ClipboardItem.tsx:471-473`），iframe 仍是 `sandbox=""`（纯只读、无脚本），底色由 `bg-white` 改为 `bg-surface`，让载入前底色与 palette 一致。

### 3.2 `src/lib/richEditor.ts` —— 编辑态取回（第一道闸，纯函数）

- `cleanEditableHtml(body: HTMLElement): string`（L27）：
  - 删注释节点、删 `style,script,link,meta,title,base`；
  - 属性白名单仅 `href/src/alt/title/colspan/rowspan`；
  - 内联 `style` 只保留：`font-weight >= 600`、`italic`、`underline` / `line-through`、`text-align`、`vertical-align`；
  - `white-space: pre-wrap / pre` 的 `span/div` → 换成真正的 `<pre>`（在清属性**之前**做，判定依据就是来源内联的 white-space）；
  - `img` 只留 `data:image/`；删空 `span`；
  - 返回 `body` 克隆的 `innerHTML`。
- `extractEditableText(body: HTMLElement): string`（L46）：优先 `innerText`（jsdom 回落 `textContent`），`NBSP → 空格`，`CRLF/CR → LF`，去末尾空白。

- `update_item_rich_content(app_handle, id, content, html)`（L290）：

### 3.5 安全模型（不要动这些前提）

- 弹窗 `allow-same-origin` **仅**用于父文档设 `designMode` / 读回内容；无 `allow-scripts`。
- srcDoc 内 CSP 不变（`default-src 'none'; img-src data:`）。
- 后端保存时再净化一次（`sanitize_clipboard_html`），不信任前端。
- **绝不要把片段 `dangerouslySetInnerHTML` 进主文档**——那会让来源 HTML 直接跑在主 WebView 里。

### 3.6 数据 / 粘贴链路

- `paste_service`：文本条目只要 `html_path` / `rtf_path` 任一存在就走 `Rich` 写回（CF_UNICODETEXT + HTML Format + Rich Text Format，字节原样）——`src-tauri/src/services/paste_service.rs:37-39`（`choose_text_write_path`）、`:99` 起（`write_rich`）。
- 编辑后条目**仅 HTML、`rtf_path = NULL`**，所以只认 RTF 的目标应用（如部分 Office 场景）格式丰富度可能下降——已在 v0.9.3 release 说明中披露。

## 4. 数据 / 格式链路与安全边界

- **便携布局（XDG 风格，全部跟 exe 走）**：`lib.rs::exe_dir` → `config/`（`settings.json` / `storage.json` 指针 / `window-state.json`）+ `data/`（`clipboard.db` / `images/` / 富文本 `formats/`）。`app_config_dir()` = `<exe目录>\config`（`lib.rs:34`），`app_data_dir_default()` = `<exe目录>\data`（`lib.rs:38`）。
- **旧布局迁移**：`migrate_legacy_layout()`（`lib.rs:44` 起）首次启动时从 `%APPDATA%/com.lyz.clipboard-manager-tauri`（`lib.rs:11` 硬编码 identifier）继承 `settings.json` / `storage.json` / `window-state.json`；无自定义存储指针时连带迁 `clipboard.db(-wal/-shm)` 与 `images/`。只在新 `config/settings.json` 不存在时跑一次。
- **富文本落盘**：条目 HTML 以 CF_HTML 字节写进 `formats_dir/edit-{id}-{millis}.html`，DB 存路径（`html_path`），粘贴时按字节原样写回剪贴板。文件名带时间戳 → 不会出现「两条记录共用同一文件、改一条变两条」。
- **净化两道闸**：前端 `cleanEditableHtml`（白名单）→ 后端 `sanitize_clipboard_html`（`clipboard.rs:583`：还原 `j` 实体、删 script 块/孤立标签、删 meta-refresh 等导航标签、删 `on*` 事件属性……）。
- **自启动**：走**任务计划程序**（`schtasks`），任务名 `ClipboardManagerAutostart`（`src-tauri/src/services/settings_service.rs:11`），`/RL HIGHEST` + `--minimized`。**不用注册表 Run 键**——提权应用（`app.manifest` 里 `requireAdministrator`）登录时不会自动弹 UAC，Run 键会被静默跳过。`lib.rs:313` 有「设置开着但任务丢了就自愈重建」的逻辑。
- **短信捕获身份链路**：稀疏包（MSIX `ClipboardManagerIdentity`）→ AUMID 激活 → `sms-helper.exe`（asInvoker）订阅通知 → 主进程读结果。相关常量见 `src-tauri/src/services/identity.rs:38/45/50`。**这条链路对包名 / 证书 / manifest 高度敏感**，见 §6。

## 5. 已知限制 / 待办

### 5.1 富文本（v0.9.3 新引入）

1. **编辑后 RTF 不再保留**（HTML-only，`rtf_path = NULL`）——只认 RTF 的目标应用格式丰富度下降。
2. **纯文本 → 富文本切换不回灌**：富文本 iframe 保留自己的编辑现场，纯文本视图里的未保存修改切回富文本会丢（富文本 → 纯文本方向会同步 textarea）。
3. `richSrcDoc` 只依赖 `richHtml`：**弹窗打开期间切主题不会立即重刷 iframe 配色**，关掉重开正常。
4. `designMode` 回车会克隆当前块的 class / 内联样式；保存时 `cleanEditableHtml` 会清掉，编辑过程中可能短暂看到。
5. Chrome 粘贴会把 `white-space:pre-wrap` 改成 `normal`，所以**粘贴进来的代码块不会自动变 `<pre>`**（本次未接管 paste 事件）。
6. 富文本 iframe 固定 `h-[46vh]`，内容短时下方有空白——不是内容丢失。

## 9. 构建与发版手册（沿用，含旧坑）

### 9.1 构建

```bash
cd D:\copy\clipboard-manager-tauri
npm run tauri build          # 或双击 build-release.bat（会先 call vcvars64.bat）
```

- **构建前必须手动清 `dist`**：`vite.config` 是 `emptyOutDir: false`，残留旧文件会被打进包。
  PowerShell 里 `Remove-Item` 会被 safe-delete 垫片静默拦截，用：
  ```powershell
  [System.IO.Directory]::Delete($p, $true)   # 删完要复核目录是否真的没了
  ```
- **先停 `sms-helper` / `sms-capture-helper` 进程**，否则链接期报 `LNK1104`。**不要杀主程序**（它持有剪贴板监听）。
- 中文 JSON / 配置文件用 **Python 以 UTF-8 写**，不要用 PowerShell 5.1 的 `Set-Content`（会写成 UTF-16/GBK）。
- 资源必须在位：`src-tauri/clipboard-identity.msix`、`clipboard-identity.cer`、`sms-helper.exe`——`beforeBuildCommand`（`tauri.conf.json:10`）会从 `identity/` 复制并现场编译 `sms-capture-helper`。

### 9.2 发版

1. 改 5 处版本号 + `version.json`（`version` / `notes` / `github`）。
2. `npm run tauri build` → 产物在 `src-tauri/target/release/bundle/nsis/` 与 `src-tauri/target/release/`。
3. 复制成 root 资产名 `clipboard-setup.exe` / `clipboard-manager-tauri.exe`（root `*.exe` 被 `.gitignore` 忽略）。
4. 打 tag `v<ver>`，推 master。
5. `gh release create v<ver> --title ... --notes-file ...` —— **省略 `--target`**（默认用当前分支 HEAD），上传两个资产。`GH_TOKEN` 的取法见 §1.4。
6. 发版后把 `version.json` 推到 master：应用检查更新读 `raw.githubusercontent.com`（主）/ jsdelivr（兜底，约 12h 缓存；校验时用 `…/gh/QikiiL/Clipboard@<commit>/version.json` 定版 URL 绕过缓存）。
7. Release body 按 §1.3 的 `## 更新内容` + `### 新功能/改进/修复/升级说明` + `## 下载` 结构写。
